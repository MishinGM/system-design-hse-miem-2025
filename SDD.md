# System Design Document

**Architectural Kata: Tales Of A Fourth Grade** — SaaS-платформа для начальной школы

*Отчёт составил: Мишин Григорий · июнь 2025 г.*

---

## Глоссарий

| Термин          | Определение                                                                 |
| --------------- | --------------------------------------------------------------------------- |
| **Student**     | Ученик, объект учёта (ФИО, класс, контакты, фото)                           |
| **Teacher**     | Преподаватель, вносит посещаемость, задания, оценки                         |
| **Parent**      | Родитель / законный представитель учащегося                                 |
| **Attendance**  | Запись о присутствии, опоздании или оправданном отсутствии                  |
| **Excuse**      | Электронное заявление об отсутствии, поданное родителем                     |
| **Assignment**  | Учебное задание с дедлайном и вложениями                                    |
| **Grade**       | Оценка, привязанная к Assignment                                            |
| **API Gateway** | Единая точка входа для клиентов, выполняет контроль доступа и маршрутизацию |
| **MVP**         | Минимально жизнеспособный продукт (первая поставка)                         |

## 1. Цели и предпосылки (Отсев + Scope Refinement)

### 1.1 Контрольные вопросы

| Вопрос                             | Ответ                                                                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **Цель стейкхолдеров**             | Сократить трудозатраты учителей на ведение журналов и устранить жалобы родителей; вывести 80 % школ-пилотов на систему ≤ 3 мес. |
| **Какую проблему решает система?** | Бумажные журналы, Excel-файлы и разрозненные мессенджеры → потери данных, штрафы Рособрнадзора.                                 |
| **Критерии успеха**                | ≥ 80 % школ-пилотов пользуются системой ежедневно; p99 латентность чтения ≤ 200 мс в учебное время; SLA 99,9 %.                 |
| **Как измерять?**                  | DAU / Retention (30 дней), метрики Prometheus, опрос удовлетворённости родителей.                                               |
| **Для кого создаётся?**            | Учителя, администраторы школы, родители. Закрываем боль «одна платформа – все процессы».                                        |
| **Если не сделаем?**               | Сохранится не-оцифрованный процесс → штрафы, потеря лояльности и времени персонала.                                             |
| **Если сорвём сроки?**             | Срыв запуска к 1 сентября 2025 — утрата учебного года, репутационные риски.                                                     |
| **Зависимости**                    | ФЗ-152, облако РФ, готовность школ к PWA, интеграции с «ЭлЖур/МЭШ» (следующая фаза).                                            |

### 1.2 Бизнес-требования (сокращённо)

* Учёт посещаемости, заданий и оценок в режиме реального времени.
* Канал «родитель ↔ учитель» с push-уведомлениями.
* Автоматическая генерация отчётов для школьной администрации.
* Запуск пилота на 100 школ, масштабируемость до 1 млн учеников.

### 1.3 Скоуп проекта

| Входит в MVP                                                                          | Не входит в MVP                                                 |
| ------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Attendance, Assignments, Grades, PDF-отчёты, заявления Excuse, RBAC, push-нотификации | Бухгалтерия, логистика школы, продвинутый форум, гос-интеграции |

## 2. Требования и ограничения

### 2.1 Функциональные требования

| ID        | User Story                                                                       | Приор.      |
| --------- | -------------------------------------------------------------------------------- | ----------- |
| **FR-01** | Как учитель хочу фиксировать посещаемость и опоздания, чтобы формировать отчёты. | ★★★         |
| **FR-02** | Как родитель хочу подать заявление об отсутствии c вложением справки.            | ★★★         |
| **FR-03** | Как администратор хочу управлять профилем ученика и классом.                     | ★★★         |
| **FR-04** | Как учитель хочу публиковать задания и выставлять оценки.                        | ★★★         |
| **FR-05** | Как администратор хочу получать PDF/HTML-отчёты по ученику или классу.           | ★★☆         |
| **FR-06** | Как пользователь хочу ролевой доступ (учитель/родитель/админ).                   | ★★★         |

| **FR-08** | Форум/чат «родитель-учитель».                                                    | ★☆☆ (Later) |

### 2.2 Нефункциональные требования

| ID         | Категория          | Требование                                                       | Приор. |
| ---------- | ------------------ | ---------------------------------------------------------------- | ------ |
| **NFT-01** | Производительность | p99 латентность: чтение ≤ 200 мс, запись ≤ 500 мс при 10 000 RPS | ★★★    |
| **NFT-02** | Масштабируемость   | Горизонтальный рост до 1 млн учеников (≈ 3 млн родителей)        | ★★★    |
| **NFT-03** | Доступность        | SLA 99,9 % (учебное время)                                       | ★★★    |
| **NFT-04** | Безопасность       | Соответствие ФЗ-152, 2FA для учителей                            | ★★★    |
| **NFT-05** | Регуляторика       | Данные храним только в РФ, шифрование ГОСТ                       | ★★★    |
| **NFT-06** | UX                 | PWA с офлайн-кэшем ≥ 15 мин                                      | ★★☆    |
| **NFT-07** | Observability      | Prometheus + Grafana, OTel-трейсы, аудит действий                | ★★☆    |

### 2.3 Расчёт нагрузки (на салфетке)

* **Активность.** MAU ≈ 4 млн (ученики + родители + учителя), DAU = 20 % → 0,8 млн.
* **Пиковый час.** 15 % от дня ⇒ 120 тыс. одновременных юзеров.
* **Средняя активность.** 2 запроса/с → \~15 000 RPS (запас × 1,5).
* **Хранение (год).** Attendance ≈ 20 GB, Grades 5 GB, прочее 2 GB ⇒ 27 GB/год.
* **Шардинг.** По `school_id`: 32 шарда PostgreSQL + Citus.
* **Сеть.** 15 000 RPS × 1 KB ≈ 15 MB/s (< 15 % 1 Gbps).

### 2.4 Ограничения

* **Облако:** Яндекс Cloud (сертификация ФЗ-152).
* **Бюджет MVP:** ≤ 5 млн ₽; запуск ≤ 6 мес.
* **Импортозамещение:** только OSS или вендоры с поддержкой в РФ.
* **Платформа:** Kubernetes + Helm, Java 19/Spring Boot, Vue 3 PWA.
* **Ключевые метрики бизнеса:** Retention, DAU, вовлечённость родителей.

## 3. Проектирование

### 3.1 High-Level Design

#### 3.1.1 Интеграции (рез-ты HW-2)

| № | From → To                          | Тип   | Технология           | Причина                       |
| - | ---------------------------------- | ----- | -------------------- | ----------------------------- |
| 1 | Client PWA → API Gateway           | sync  | HTTPS REST / GraphQL | UX < 200 мс                   |
| 2 | Gateway → Auth & IAM               | sync  | REST + JWT           | Валидация доступа             |
| 3 | Gateway → STUD/ATTN/ASGN           | sync  | REST                 | CRUD-операции                 |
| 4 | STUD/ATTN/ASGN → Reporting         | async | Kafka topic          | Фан-аут, задержка не критична |
| 5 | ASGN → Notification                | async | Kafka + DLQ          | Push после оценки             |
| 6 | Notification → Client              | async | WebSocket/SSE        | Real-time                     |
| 7 | Gateway → File Store               | sync  | Signed S3 URL        | Большие файлы                 |
| 8 | External Integration ⇆ Гос-системы | mixed | REST / SFTP batch    | Будущая фаза                  |

#### 3.1.2 Данные (рез-ты HW-3)

* **OLTP** — PostgreSQL 15

  * `STUD` – профиль ученика (`student`, `class`).
  * `ATTN` – attendance (партиции по месяцу, шардинг по `school_id`).
  * `ASGN` – assignment, submission, grade (FK, транзакции).
* **OLAP** — ClickHouse 23: агрегаты Attendance + Grades, партиции YYYYMM, шардинг по `school_id`.
* **Cache/Stream** — Redis 7 Cluster (Push TTL 48 h).
* **Blob** — MinIO S3 (сканы справок, PDF-отчёты).

#### 3.1.3 Концептуальная схема (C4 Context + Container)

* **API Gateway (Kong):** TLS-termination, RBAC, rate-limit.
* **Auth & IAM (Keycloak):** OAuth 2.1/OIDC, 2FA.
* **Business Services:** STUD, ATTN, ASGN (Spring Boot), каждое со своей БД.
* **Reporting:** consumer Kafka, формирует PDF, кладёт в MinIO, шлёт ссылку.
* **Notification:** consumer Kafka, Redis Streams → WebSocket-Hub → PWA.
* **File Store:** MinIO 6+2 erasure.
* **Kafka:** 3 брокера, KRaft.
* **Observability:** OTel Collector → Prometheus / Loki / Tempo / Grafana.
* **CI/CD:** GitLab CI → Helm → ArgoCD (Canary, GitOps).

### 3.2 Deep Dive (HW-4)

| Компонент                 | Что решает                                   | Ключевые детали                         |
| ------------------------- | -------------------------------------------- | --------------------------------------- |
| **L7 Load Balancer**      | Горизонтальная масштабируемость, TLS-offload | Yandex ALB HTTP/gRPC                    |
| **WAF / Anti-DDoS**       | Защита OWASP Top 10, L7-атаки                | Cloudflare WAF + Yandex DDoS Protection |
| **IdP (SSO)**             | Централизованная аутентификация, 2FA         | Keycloak 23 (HA кластер)                |
| **CDN**                   | Раздача PWA / PDF из edge                    | Cloudflare CDN + MinIO origin           |
| **Redis Side-cache**      | Снижение latency на горячих данных           | TTL 30 с, cache-aside                   |
| **Service Mesh (Istio)**  | mTLS, retries, circuit breaker               | Envoy sidecar, OTel ingress             |
| **CI/CD (GitLab→ArgoCD)** | Rollout, quality gates (SAST/DAST)           | Canary deploy, auto-rollback            |
| **Back-up**               | RPO ≤ 1 мин                                  | pgBackRest + S3 Glacier, CH-backup      |

### 3.3 Итоговая архитектура

```
User (Parent/Teacher) → PWA → API Gateway → Business Services
  • События Kafka
  • MinIO / Redis / PostgreSQL 15 (Citus)
  • Observability stack
  • CI/CD GitOps
```

Архитектура обеспечивает:

* **Горизонтальную масштабируемость** (шардинг PostgreSQL, k8s HPA).
* **SLA 99,9 %** через мульти-AZ, LB, репликации.
* **Соответствие ФЗ-152** (хранение в РФ, шифрование at-rest/in-transit).
* **TCO** ≤ 5 млн ₽/год на 1 млн учеников.

## 4. Вывод

MVP реально запустить к 1 сентября 2025 г. при бюджете ≤ 5 млн ₽ и команде 10 FTE (5 BE, 2 FE, 1 DevOps, 1 QA, 1 PM).
Основные риски:

* Регуляторика (аудит ФЗ-152)
* Обучение пользователей (план B – on-prem DR)

Система готова к пилоту на 100 школ и масштабированию до 1 млн учеников без радикального рефакторинга.
