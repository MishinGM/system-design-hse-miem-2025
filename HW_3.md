## 4. Шардирование и партиционирование

### 4.1 PostgreSQL / Citus

* **Таблица `attendance`** — рост 10–20 GB/год.
* **Партиции по месяцу** (range `date`): быстрое удаление старых лет.
* **Шардирование** — `hash_mod(school_id)` → 32 шардов (добавляем ещё 32 при росте).
* Gateway кладёт `X-School-Id`; Citus‑coordinator роутит запрос.

### 4.2 ClickHouse

* **Шарды** по `school_id`, внутри шарда партиции `YYYYMM`.
* **2 реплики** в каждом шарде → чтение/фейловер.
* **TTL 36 мес** → автоматический drop архивов.

### 4.3 Redis

* **Hash‑slot** алгоритм распределяет ключи Stream‑id; ручных действий не нужно.

## 5. Обоснование выбора СУБД

1. **ACID‑операции** («оценка», «смена статуса») → PostgreSQL (транзакции, FK).
2. **Mass‑read отчёты** (100 GB+/год) → ClickHouse (колоночные агрегации, SIMD).
3. **<10 мс push‑уведомления, TTL 48 h** → Redis Streams.
4. **Файлы‑сканы** → объектное хранилище → MinIO (S3‑api, erasure‑coding).
5. **ФЗ‑152**: шифрование at‑rest (pgcrypto, CH‑disk‑encryption, MinIO‑SSE).
